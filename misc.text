Type A:
The first script is the pipeline submission wrapper. It sets YEAR, MONTH, and MODEL, then submits three SLURM jobs in order. The first job, submit_month_type_A.sh, is a SLURM array job that creates 31 tasks, where each task gets a different day through SLURM_ARRAY_TASK_ID and runs the Python program for one day of data. The second job, daily_to_monthly_pkl.sh, waits until the first job finishes successfully because of --dependency=afterok:$jid1; it then merges the daily outputs into a monthly pickle. The third job, copy_from_pickle_to_database.sh, waits until the second job finishes successfully because of --dependency=afterok:$jid2; it then copies the monthly pickle data into the database. All three jobs receive the same YEAR, MONTH, and MODEL variables through sbatch --export.

For type B:
The Type B wrapper script sets YEAR, MONTH, and MODEL, then submits submit_month_type_B.sh as a single SLURM job. Unlike Type A, this worker script does not use an array job, so it runs only once for the selected month/model. It still builds a DATE_STR using YEAR, MONTH, and a dummy DAY=1, because the Python program expects a full date string. The Python command then generates the monthly or mostly aggregated digest output directly. After this first job finishes successfully, copy_from_pickle_to_database.sh runs because of --dependency=afterok:$jid1, and copies the generated pickle data into the database. Both jobs receive the same YEAR, MONTH, and MODEL variables through sbatch --export.
